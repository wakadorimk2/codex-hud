# 旧Hook方式の歴史資料

この文書は、以前のHook起点方式を記録するために残します。

現行方式はHookを状態同期に使いません。

## 以前の方式

以前は、Codex Hookが`CodexHud.exe --hook`へ入力を渡し、Named Pipe経由で状態Storeを更新していました。

JSONLは補助経路でした。

Hook通知をセッション集合の起点にすると、Hookの欠落、重複、遅延でランプ数がずれる問題がありました。

そのため、現行方式はローカルJSONLの再探索をセッション集合の起点にします。

## 現行の扱い

- 通常起動はHookを待ちません。
- `--hook`は互換用の即時終了です。
- インストーラーはHook設定を読み書きしません。
- アンインストーラーはHook設定を変更しません。
- `install-hooks.ps1`は手動移行用の旧資料です。

## 未確認のこと

Codex内部のHookイベントschemaを現行機能の前提にしません。

承認待ち、質問待ち、回答待ちの判定は現行HUDの責務ではありません。

現行の`Listening`は、JSONLから確認できる最近の活動だけを示します。
